## UX contract — My Submissions

- In the Action column, **Draft incomplete:** icon-only **Edit**; **Draft complete and saved:** icon-only **Edit + Submit**; **Submitted:** icon-only **View**. Each icon has an accessible label and tooltip.
- Submit availability is computed from **saved server-side** paper metadata; unsaved changes in the editor cannot unlock it. Paper Editor remains a Save Draft workflow; it does not contain a Submit control.
- Clicking Submit opens a confirmation modal with Paper ID and consequences. Cancel has no side effects. Confirm invokes a guarded server Action and closes the modal only after success.
- Submitted paper details route is owner-only read-only, displaying title, track, ordered author affiliations, abstract, keywords, private PDF download and history; author emails are not exposed in the read-only directory view.
- Directory counts now show My Papers / Saved Drafts / Submitted; outdated ACAD-002 banner was replaced. Horizontal table scrolling is contained inside the table at narrow mobile widths; desktop does not require a horizontal table scrollbar at 1440px.

## Server-side eligibility contract

All of these **must already be persisted**: valid paper title, active conference track, at least one valid author with exactly one corresponding author and valid ROR or explicit manual affiliation, nonempty abstract text, at least one nonduplicate keyword, and an existing PDF under the authenticated owner's correct private namespace with valid saved metadata.

Retained technical safeguards from ACAD-003: abstract text max 10,000 characters, keywords 2–80 characters and up to 15 tags, stored PDF max 10 MB. **No official minimum/maximum academic word count or official keyword count was invented**. These are completion checks, not final academic publication guidelines.

The seven TOR milestone dates remain **planning records only**, not automatic hard date gates. This task does not open or close submission based on dates. The future owner-approved academic rules/date window must be applied before public production launch.

## Persistence, safety, timeline

- Additive migration `2026_11_21_000005_add_paper_submission_tracking.php`: nullable `submitted_at`, `submission_version` (Draft = 0, first Submitted = 1) and `paper_status_histories` table with actor/from/to/version/timestamp and unique per-paper event+version.
- `App\Actions\Conference\SubmitPaper` reloads the paper with a DB row lock inside a transaction, reauthorizes its owner, rechecks Draft status and all current stored data/PDF, then updates status/timestamp/version and appends the history event in the **same transaction**.
- Second submit / stale modal cannot create another submission or duplicate event. Saving or editing a Submitted paper remains blocked by the existing PaperPolicy and SavePaperDraft checks.
- Paper reference, ULID, author IDs, track and PDF path are not regenerated by Submit.
- `Submitted` is immediately eligible for the future Reviewer Index (REV-001), with **no separate administrative screening**. No Reviewer claim or review experience is implemented in this task.
- Owner-only routes and role policies remain in place. The timeline presents dates in Asia/Jakarta (WIB), while preserving normal database timestamps.
- This task does **not** send submission emails; COM-01/COM-02 remain distinct messaging work.
